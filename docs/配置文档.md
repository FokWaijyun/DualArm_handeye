# DualArm_handeye 环境配置与启动

本文说明如何在 Ubuntu 22.04 宿主机上手动配置 `DualArm_handeye` 的运行环境。

项目使用 ROS 2 Humble、Conda Python 3.10 和 X5 SDK 3.4.9。手眼标定 GUI、ROS 2 Python 模块、OpenCV、PyQt5 和 X5 SDK 在同一个 Python 3.10 进程中运行，不使用 Docker 和 X5 HTTP bridge。

本文只提供命令和检查方法，不会自动创建或修改 Conda 环境。

## 环境组成

| 组件 | 运行环境 | 作用 |
| --- | --- | --- |
| Orbbec ROS 2 驱动 | 宿主机 ROS 2 Humble | 发布相机图像和 `CameraInfo` |
| 手眼标定 GUI | Conda `handeye`，Python 3.10 | 订阅 ROS 2 话题、显示棋盘格、采样和计算标定结果 |
| X5 SDK | Conda `handeye`，Python 3.10 | 直接连接选中的机械臂，读取位姿和执行低速手动点动 |

ROS 2 环境必须通过 `source /opt/ros/humble/setup.bash` 配置。该命令设置 ROS 2 命令、Python 模块路径、共享库路径和 DDS 运行环境。Conda 环境只负责 Python 解释器和项目依赖，不能替代 ROS 2 setup。

## 前置检查

确认系统版本和 ROS 2 Humble：

```bash
lsb_release -a
test -f /opt/ros/humble/setup.bash
```

确认 Conda 可用：

```bash
command -v conda
conda --version
conda env list
```

进入项目目录：

```bash
cd /home/huo/project/DualArm_handeye
```

## 安装系统依赖

以下命令需要管理员权限。系统依赖只安装一次：

```bash
sudo apt update
sudo apt install \
  ros-humble-orbbec-camera \
  ros-humble-compressed-image-transport \
  ros-humble-camera-info-manager \
  ros-humble-diagnostic-updater \
  python3.10 \
  python3-pytest
```

如果需要使用 USB Orbbec 相机，安装设备规则：

```bash
sudo install -m 644 \
  /opt/ros/humble/share/orbbec_camera/udev/99-obsensor-libusb.rules \
  /etc/udev/rules.d/99-obsensor-libusb.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

重新插拔相机后，再检查 USB 设备权限。

## 手动创建 Conda 环境

建议使用独立环境，避免修改现有的 `x5` 环境：

```bash
conda create -n handeye python=3.10
conda activate handeye
```

安装 Python 依赖：

```bash
conda install -c conda-forge \
  numpy \
  opencv \
  pyqt \
  pyyaml \
  pytest
```

安装本项目使用的 X5 SDK 3.4.9。该 wheel 是 Python 3.10、Linux x86_64 版本：

```bash
python -m pip install ./SDK/xapi-3.4.9-cp310-cp310-linux_x86_64.whl
```

检查解释器和主要包：

```bash
python --version
python -c 'import numpy, cv2, yaml, PyQt5, xapi.api as x5; print(x5.__version__, x5.__file__)'
```

预期 Python 版本为 3.10，`xapi.api.__version__` 为 `3.4.9`。

## 每次运行前加载环境

每个新的终端都需要分别执行以下命令：

```bash
cd /home/huo/project/DualArm_handeye
source /opt/ros/humble/setup.bash
conda activate handeye
```

如果当前 shell 尚未初始化 Conda，可以直接加载 Conda 脚本：

```bash
source /home/huo/miniconda3/etc/profile.d/conda.sh
conda activate handeye
```

确认当前终端没有误用系统 Python 或 Conda base：

```bash
which python
python --version
echo "ROS_DISTRO=$ROS_DISTRO"
echo "AMENT_PREFIX_PATH=$AMENT_PREFIX_PATH"
```

`which python` 应指向类似下面的路径：

```text
/home/huo/miniconda3/envs/handeye/bin/python
```

## 首次连接 X5 网线

保持机器人伺服关闭，确认其他客户端已释放控制器。从示教器或现场配置确认所选机械臂的控制器 IPv4 地址和子网掩码。网线直连后，在宿主机查看网卡名称和地址：

```bash
ip -br link
ip -br addr
```

下面以控制器 `192.168.1.9/24` 或 `192.168.1.10/24` 为例。你的左臂是 `192.168.1.9`，右臂是 `192.168.1.10`。若直连网卡尚无同网段地址，给它临时添加一个没有被机器人占用的本机地址。先替换 `enp3s0` 为实际网卡名，并按现场网段调整地址：

```bash
robot_iface=enp3s0
sudo ip link set dev "$robot_iface" up
sudo ip addr add 192.168.1.100/24 dev "$robot_iface"
```

确认链路和路由：

```bash
ip -4 route get 192.168.1.10
ping -I 192.168.1.100 -c 3 192.168.1.10
```

`ip route get` 输出中的 `dev` 应为直连网卡，`src` 应为该网卡的本机 IPv4 地址。若使用已有地址，`ping -I` 也换成该地址。能 ping 通说明 IP 链路可达，SDK 通信由下一步确认。左臂和右臂共用同一个本机源地址即可，分别填写控制器地址 `192.168.1.9` 或 `192.168.1.10`。

在已加载 ROS 2 和 Conda 的终端按下文启动 GUI。选择对应的左臂或右臂，填写实际的“X5 控制器 IP”和路由显示的“本机源 IP”。点“诊断 X5”核对源地址，再点“连接所选臂”。看到“已连接，TF0”后，保持伺服关闭并点击“只读检查”确认位姿回读。GUI 连接时会选择 TF0，遇到控制器报警时会尝试复位。

网卡临时地址重启后会消失。确认通信正常后，再按现场网络管理方式配置永久地址。

## 验证 ROS 2 和 Conda 的组合

在同一个已经加载 ROS 2 和 Conda 的终端中执行：

```bash
python - <<'PY'
import cv2
import numpy
import rclpy
import yaml
import xapi.api
from PyQt5 import QtWidgets
from sensor_msgs.msg import CameraInfo, CompressedImage

print("Python 环境：", __import__("sys").executable)
print("Python 版本：", __import__("sys").version.split()[0])
print("OpenCV 版本：", cv2.__version__)
print("NumPy 版本：", numpy.__version__)
print("rclpy：", rclpy.__file__)
print("xapi：", xapi.api.__version__, xapi.api.__file__)
print("ROS 消息：", CameraInfo.__name__, CompressedImage.__name__)
print("依赖检查通过")
PY
```

如果 `rclpy` 或 `sensor_msgs` 无法导入，先确认当前终端执行过：

```bash
source /opt/ros/humble/setup.bash
```

如果错误中出现 `numpy`、`cv2`、`PyQt5` 或 `xapi`，检查 Conda 环境是否正确激活，以及对应依赖是否安装在 `handeye` 环境中。

## 启动宿主机相机驱动

相机启动前，确认 XiaoTop 或其他程序已经释放相机设备。相机驱动使用独立终端，不需要激活 Conda：

```bash
cd /home/huo/project/DualArm_handeye
source /opt/ros/humble/setup.bash
SERIAL_NUMBER=YOUR_CAMERA_SERIAL bash scripts/start_camera.sh
```

用 `ros2 run orbbec_camera list_devices_node` 查询序列号。现场设备上报为 Gemini 335L，序列号为 `CP253530003C`。

项目脚本使用 `gemini_330_series.launch.py`，并设置 `camera_name:=camera_01`。GUI 在以下两个话题同时可见时列出 `camera_01`。

```text
/camera_01/color/image_raw/compressed
/camera_01/color/camera_info
```

在另一个已加载 ROS 2 的终端检查话题：

```bash
source /opt/ros/humble/setup.bash
ros2 topic list -t | grep -E '^/camera_01/color/(image_raw/compressed|camera_info) '
ros2 topic info -v /camera_01/color/image_raw/compressed
ros2 topic info -v /camera_01/color/camera_info
```

必须确认有发布者，并且能够持续收到图像和内参。

## 启动手眼标定 GUI

GUI 使用与验证命令相同的 ROS 2 和 Conda 环境：

```bash
cd /home/huo/project/DualArm_handeye
source /opt/ros/humble/setup.bash
conda activate handeye
python scripts/x5_handeye_calibration.py --handeye-mode eye_to_hand
```

使用腕部相机进行眼在手上标定：

```bash
python scripts/x5_handeye_calibration.py --handeye-mode eye_in_hand
```

从 YAML 预填左右臂地址。现场地址写入被 Git 忽略的 `config/x5.local.yaml`：

```bash
cp config/x5.example.yaml config/x5.local.yaml
```

填写内容：

```yaml
arms:
  left:
    controller_ip: '192.168.1.9'
    source_ip: '192.168.1.211'
  right:
    controller_ip: '192.168.1.10'
    source_ip: '192.168.1.211'
```

手动填写 `config/x5.local.yaml` 后启动：

```bash
python scripts/x5_handeye_calibration.py \
  --x5-config config/x5.local.yaml \
  --handeye-mode eye_to_hand
```

如果文件存在，启动时即使省略 `--x5-config` 也会自动读取它。切换左臂或右臂后，界面会自动填入该臂对应的控制器 IP 和本机源 IP。

也可以不创建配置文件，直接在 GUI 中填写本次标定使用的控制器 IP 和源 IP。

## 离线重算和测试

离线重算不需要相机、ROS 话题或机械臂连接，但仍使用同一个 Conda 环境：

```bash
cd /home/huo/project/DualArm_handeye
source /opt/ros/humble/setup.bash
conda activate handeye
python scripts/x5_handeye_calibration.py \
  --recompute-samples /path/to/raw-samples \
  --handeye-mode eye_to_hand
```

运行测试：

```bash
QT_QPA_PLATFORM=offscreen \
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
python -m pytest -q
```

检查 Python 和 Shell 语法：

```bash
python -m py_compile scripts/*.py X5/*.py test/*.py
bash -n scripts/start_camera.sh
```

## 运行边界

- GUI 只订阅已运行的 Orbbec ROS 2 话题，不启动、停止或杀死相机驱动。
- GUI 一次只连接一台 X5 控制器。切换机械臂前，先关闭伺服并断开当前连接。
- 任何使能伺服、点动和采样操作前，确认工作区无人、速度足够低、急停可用。
- `source /opt/ros/humble/setup.bash` 和 `conda activate handeye` 只配置当前终端，不会永久修改系统环境。
- 标定结果写入 `handeye_samples/<left|right>/<会话>/<相机>/`，原始样本和最终 JSON/NPZ 不应提交到代码仓库。
